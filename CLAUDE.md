# Telegram Saver

Личный архиватор Telegram: Telethon (asyncio) → SQLAlchemy (SQLite, схема под PostgreSQL) → веб-интерфейс
(Jinja2 + vanilla JS, ответы JSON с HTML-фрагментами). Однопользовательское приложение, состояние глобальное.
Подробности - в `README.md`.

## Текущая задача
Миграция веб-слоя с Flask на FastAPI завершена (шаги 0-13). Раздел «После миграции» (P1-P24, кроме P12, P21, P22) выполнен.
Осталось: «Открытые наблюдения и копилка» (P12, P21, P22: ждут воспроизведения или пополняются замечаниями;
поведение там менять можно) и «Перспективные работы». План и статус: `MIGRATION_PLAN.md`.

## Правила работы
- Одна сессия = один шаг, пункт или блок пунктов плана. Читай `MIGRATION_PLAN.md`, делай только свое, отметь `[x]`
  и запиши под пунктом решения и результат. Пункты `P` держи по порядку номеров.
- Пункты «После миграции»: сначала обсудить решение с пользователем (вариант, место в интерфейсе, формат), потом делать.
- Бизнес-логику, модели SQLAlchemy и схему БД не менять без явной просьбы.
- `telegram_handler.py`: бизнес-логику работы с Telegram не менять, но саму работу с Telethon (инициализация,
  event loop, потоки) можно оптимизировать. Каждый такой случай сначала уточнять у пользователя.
- Telethon: sync-роуты (`def`) + общий замок (временное решение). Async-вариант и замена замка - только в
  перспективных работах (`MIGRATION_PLAN.md`).
- Нет аналога механизму Flask → сначала предложить замену и дождаться подтверждения.
- Долгие фоновые задачи - через `lifespan` или отдельный процесс, не `BackgroundTasks`.
- Каждое изменение объяснять 1-2 фразами: что и почему.
- Не коммитить и не пушить: коммитит пользователь в PyCharm. В конце шага дай готовый текст коммита.
- Не запускать код, который подключается к Telegram, без просьбы (запрашивает вход и ходит в сеть).

## Ключевые факты
- Запуск: `python telegram_saver.py` (запускатель uvicorn, порт 5000) или `uvicorn web.main:app`.
- Конфиг: `configs/config.py` (`BASE_DIR`, `PROFILE`, `HOST`/`PORT`, `FormCfg`, `ProjectDirs`); секреты в
  `configs/.env<PROFILE>` (не в git). Профиль - переменная окружения `TELEGRAM_SAVER_PROFILE`; пути `ProjectDirs`
  абсолютные (в тестах подменяются на временные в `conftest.py`, `media_dir_name` - URL-префикс медиа).
- Файлы: `telegram_handler.py`, `database_handler.py`, `utils.py` (`status_messages`, `format_files_report`),
  `web/` (роуты и `deps.py` с глобалами Jinja), `templates/`, `static/js/my_scripts.js`.
- Интерфейс: роуты отдают JSON, ключи = `id` элементов (`updateElementsFromResponse`). Кнопки, которым нужен выбор:
  `data-needs-checked` (отмеченные чек-боксы) и `data-needs-selected` (строка списка) + `updateCheckedDependentButtons`.
  Новый список (диалог, фильтры) прокручивается в начало (`resetScroll`), сохранение и удаление положение не трогают.
- Строка вложений в списках не хранится: считается при показе по типам файлов (`format_files_report`); столбца в БД нет.
- Python >= 3.14, менеджер зависимостей Poetry. Тесты: pytest, Telethon мокается; тестов JS нет, скрипты проверять
  в браузере на тестовой странице без Telegram. После правок: статика - `Ctrl+F5`, шаблоны - `F5`, Python - перезапуск.
- Репозиторий публичный: не добавлять в git `.env*`, `*.db`, `*.session`, `media_storage/`.
- Комментарии и docstring в коде двуязычные (EN / RU) - сохранять этот стиль, стиль PEP 8, длина строки 120.
